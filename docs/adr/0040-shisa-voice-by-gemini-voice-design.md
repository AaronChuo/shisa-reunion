# ADR-0040：西薩的聲音用 Gemini 聲音設計

- 狀態：已採用
- 日期：2026-11-19
- 延續：[ADR-0021](0021-azure-narration.md)

## 背景

ADR-0021 讓旁白和西薩都用 Azure 的曉臻預先錄好。旁白很好；西薩只是同一個聲音調高 30%、快 10%，聽起來像旁白在學角色，不像西薩自己在說話。當時試過 Azure 支援台灣國語的兒童聲音，沒有更好的。

Gemini 3.8 Flash TTS 可以用一段描述設計出新的聲音（聲音設計），每句再用文字指示語氣，比只能調音高和速度更有表情。

## 決策

- **旁白不換**：「念給我聽」、開場故事、明信片照舊用 Azure 曉臻，已經錄好的不重錄
- **只有西薩換成 Gemini 設計的聲音**：
  - 先試了四種描述（元氣小跟班、軟綿綿、憨厚小獅子、節目主持人），和現在的西薩放在一起一句一句比較，選了「元氣小跟班」：活潑的配音員演卡通裡的小跟班，明亮、偏高、有點調皮
  - 描述只能寫成「成年配音員演卡通角色」：直接描述小孩的聲音，會被聲音設計的安全政策擋掉
  - 語言設為 `zh-TW`，描述裡寫明台灣口音
- **略慢 8% 用後製，不用指示**：在語氣指示裡要求「稍微慢一點」重錄，只有部分句子變慢，有些反而變快，還多出「欸」「嗯」之類的語氣詞。改成照原本的速度錄，再用 ffmpeg 的 `atempo` 每句放慢到 0.92 倍，音高不變，速度一致
- **一句一個請求**：每句有自己的語氣指示（`speech_metadata.style`），只給錄音腳本用，不影響檔名
- **錄完要聽**：生成式語音偶爾會多一個字（試錄時把「這站」念成「這一站」）、少一個字，或在句子前面多一聲吸氣。腳本可以只重錄某一句（`pnpm voice --again "<句子>"`）
- **音量對齊旁白**：去掉頭尾靜音，響度調到 −19 LUFS（Azure 旁白約 −19），格式和旁白一樣是 MP3、24 kHz、48 kbps、單聲道
- **檔名**：設定加上 `engine` 欄位。Azure 的檔名算法和原本一字不差，所以旁白的錄音不會因為這次改動重錄；Gemini 的檔名用模型、聲音 id 和速度加上文字計算
- **揭露**：「素材來源」寫明旁白是 Azure 合成、西薩的聲音是 Gemini 聲音設計

## 影響

- 錄西薩的句子需要 `.env.local` 裡的 `GEMINI_API_KEY` 和本機的 ffmpeg；Gemini 用預付額度，三句不到 0.01 美元
- 設計好的聲音存在金鑰所屬的 Google 專案裡，一年沒用會被刪掉。描述寫在 `src/audio/voice.ts`，但重新設計會得到不同的聲音，那時西薩的每一句都要重錄
- 商業化前，和 Azure 的付費層重錄一起，確認 Gemini API 條款對合成音檔的使用範圍（#15）

## 替代方案

- **整批換成 Gemini**：旁白已經夠好，而且生成式語音每次念的不一樣、每句都要聽；換掉的好處抵不過重錄和檢查的成本
- **Azure 的兒童聲音**：ADR-0021 時試過，不夠自然
- **在語氣指示裡要求放慢**：速度不平均、多出語氣詞（見上）
- **真人配音**：最好聽，但每次改字都要重錄；之後若要上架可以再考慮
